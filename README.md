# Student Deadline Tracker

**Призначення:** Застосунок для відстеження дедлайнів лабораторних та модульних робіт.
**Користувач:** Студент, якому потрібно контролювати свої успіхи та борги з навчання.
**Основні сценарії:** Створення завдання, прив'язка його до певного курсу, фільтрація незданих робіт.
**Сутності:** 
1. `Assignment` (навчальне завдання)
2. `Course` (навчальна дисципліна, яка містить список завдань)

## Реалізація конструкцій Swift
- **struct, class, protocol, enum, колекції**: реалізовані у файлі `Models.swift`.
- **Безпечне розгортання (if let) та сценарії**: реалізовані у файлі `ViewController.swift` у методі `viewDidLoad()`.

## Обґрунтування вибору типів (struct vs class)
- `Assignment` реалізовано як `struct`, оскільки це проста модель даних (Value Type), яка передається копіюванням і не має власного життєвого циклу чи складного спільного стану.
- `Course` реалізовано як `class` (Reference Type), оскільки це об'єкт, який керує колекцією завдань. Нам потрібно, щоб зміни в курсі (наприклад, додавання нового завдання) відображалися в усіх посиланнях на цей об'єкт.

Архітектура: MVC (Model-View-Controller)
- Model: Зберігає дані (Assignment, Course) та бізнес-логіку (фільтрація, зміна статусів).
- View: Відповідає за відображення UI (наразі виведення в консоль/прості UI елементи).
- Controller: Отримує дії від View, оновлює Model, і навпаки.

## Архітектура та Патерни (Лабораторна 2)
- **Архітектура:** MVC (відбулося розділення файлів на Models, Views, Controllers).
- **Породжувальний патерн (Builder):** `AssignmentBuilder` — створює об'єкти завдань покроково.
- **Структурний патерн (Adapter):** `TypeAdapter` — адаптує рядковий ввід у тип AssignmentType.
- **Поведінковий патерн (Strategy):** `SortStrategy` — інкапсулює алгоритми сортування (за алфавітом, за боргом).
- **Виправлені антипатерни:** Уникнення Massive View Controller через винесення логіки сортування та створення об'єктів у шар Services.

## Демонстрація принципів SOLID
* **S (Single Responsibility):** Розділення відповідальностей. `ViewController` не займається сортуванням чи генерацією об'єктів. Це винесено в `SortStrategy` та `AssignmentBuilder`.
* **O (Open/Closed):** Проєкт відкритий для розширення. Щоб додати нове сортування, ми просто створимо нову структуру, що підписується під `SortStrategy`, не змінюючи старий код.
* **L (Liskov Substitution):** Скрізь, де вимагається `SortStrategy`, можна підставити будь-яку його реалізацію (`AlphabeticalSortStrategy` або `DebtSortStrategy`).
* **I (Interface Segregation):** Протоколи сфокусовані та компактні. `SortStrategy` має лише один метод `sort()`.
* **D (Dependency Inversion):** `ViewController` залежить від абстрактного протоколу `TaskRepository`, а не від конкретного джерела даних. Це дозволило підставити `MockTaskRepository` для тестування.
